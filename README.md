# Network Lens 桌面网络诊断助手

面向普通办公用户的桌面诊断助手。默认进入“网络检查”，自动检查所有已收录 API 提供商与聚合服务的端点，不携带凭据；切换菜单不会重复启动，支持停止与重新检查。“本机应用”独立展示已确认安装的工具，支持置顶、候选核对和手动确认程序位置。工具详情区分宿主、CLI 与已识别的用户级扩展，显示版本、功能、官方说明与适配缺口。网页平台目录默认折叠，点击检查后才发送探测。系统网络、补充直连和代理路径分别呈现结果。专业诊断收在“高级排查”中。

本机发现已扩展至 21 类工具，支持未运行应用、改名应用、应用链接、常见 CLI 与 NVM/fnm 安装位置；桌面、CLI 和 Agent 扩展版本分别展示。点击“检查更新”查询公开发布源，查看本机/发布版本、渠道、时间与更新提示；未知来源和查询失败不会显示成最新。实机范围与限制见 [工具识别与更新验收](docs/validation/TOOL-DISCOVERY-VALIDATION.md)。

新增“文件策略与审计”：先选择项目或目录，只枚举元数据；确认候选后分别设置读取、修改、发送模型策略，支持指定文件、版本冲突保护、自检记录、提醒确认和脱敏报告预览/保存。**当前仅实现助手自己的策略校验与记录，不采集第三方 AI 工具访问，也不能阻止其文件访问。** 专用自动修复、受控文件网关、隔离启动、OS 审计与系统阻断尚未实现，文档完整验收仍未达成。逐项范围见 [补充实现与验收](docs/validation/ASSISTANT-VALIDATION.md)。已有 release 安装包仍是此前构建，使用源码构建运行查看本轮功能。

默认覆盖：豆包、DeepSeek、Kimi、腾讯元宝、千问、WPS AI、飞书 AI、ChatGPT、Claude、Gemini、Microsoft Copilot、Perplexity、Notion AI、Cursor。按“国内 / 海外 / 需要关注 / 正在运行”筛选，支持名称搜索。

平台检查的范围是公开网页入口，不把产品官网的连接成功当作 AI 对话、企业租户或客户端后端全部可用。程序不登录账号、不读取浏览器历史或 Cookie、不发送聊天或上传内容。所有状态来自这台电脑的本次探测，示例模式会明确提示。

## 打开程序

本机生成的 Apple Silicon 应用：`release/mac-arm64/Network Lens.app`。可在 Finder 中双击，或复制到应用程序目录。此构建没有开发者签名和公证，用于本机开发验收，尚不是签名发布版本。

便于复制的 macOS 压缩包：`release/Network-Lens-macOS-arm64.zip`；Windows x64 安装包：`release/Network Lens Setup 0.3.0.exe`。安装包未配置发布签名。顺序排查验收见 [0.3 记录](docs/validation/TRIAGE-VALIDATION.md)，文件校验值见 [0.3 checksums](checksums-0.3.0.txt)；普通用户版原验收见 [0.2 记录](docs/validation/OFFICE-VALIDATION.md)，专业版保留在 [0.1 记录](docs/validation/VALIDATION.md)。

源码运行需要 Node.js 22.12 以上，建议 Node.js 24 LTS：

```sh
npm ci
npm run build
npm start
```

开发模式：`npm run dev`。仅 UI 预览：`npm run preview`，浏览器访问 `http://127.0.0.1:5173/`，此时明确显示演示模式，不具备原生采集能力。桌面应用本身不开启本地 HTTP 服务。

macOS 打包：`npm run package`。Windows x64 安装包：`npm run package:win`。跨平台生成安装包不代表已在该平台验证；Windows 采集仍需 Windows 11 实机验收。

## 普通用户使用流程

1. 打开程序，后台核验系统/用户应用目录、应用标识、PATH 与常见 CLI/NVM 安装位置；默认只显示已确认安装记录，未确认与历史记录在“全部工具与候选”中。
2. 打开工具详情，选择组件与失败功能。点击“诊断所选功能”，输入用户确认的端点；开始时从主进程冻结工具身份、组件版本和运行位置，不能由前端伪造版本或适配状态。处理后在工具原功能中复测。
3. 展开网页平台目录，点击“开始检查网页入口”或“单独测试”进行通用入口检查；未安装平台也可用于网页入口检查。点击“查看建议”可打开平台官网或复制结果给 IT 同事。复制内容仅含平台入口、状态、路径和阶段错误码，不含进程路径、代理端点或原始自由文本。
4. 需要时点击“停止检查”；已经完成的结果保留。30 秒内不会重复检查同一个平台，避免高频请求。

遇到连接异常或频繁重连，点击“按顺序排查”，可选择 Codex 或原有平台。依次检查基础网络、代理入口、DNS、安全连接及平台响应，并根据证据推荐优先处理项。按钮可打开对应设置、官方入口、复制结果或重建诊断器自身连接；不会自动修改 VPN。处理后复测并在原工具确认恢复。入口检查正常但仍重连，可开启 60 秒网络 / TCP 快照观察并标记出错时刻，未验证真实流式连接。详见 [顺序排查与修复交互](docs/plans/顺序排查与修复交互.md)。

系统路径使用 Electron / Chromium 的系统代理和证书处理，HEAD 根路径检查不跟随重定向。每次最多同时检查 4 个平台，每个平台总预算 18 秒。收到 HTTP 状态码就明确报告 HTTP 结果；系统路径失败时会分别列出补充直连和代理结果，标明每条路径是否可访问。只有检查执行未完成才显示“检测未完成”，TLS 成功但未收到 HTTP 响应则明确显示两阶段状态。

VPN、地区策略、分流 DNS 和本机代理端口的人工排查请见 [VPN 网络访问检查和处理方案](docs/plans/VPN-网络访问检查和处理方案.md)。该方案不自动修改 VPN 配置。

401 说明此次无登录凭据请求要求认证，不判断用户账号是否失效；403 / 451 归为访问限制；429 或服务异常响应提示稍后再试，不宣布平台全球故障。认证、验证码、账号权限和真实生成任务需用户在对应工具中复测。

进程识别仅按精确名称及已知 Helper 名称匹配，不根据 IP 猜测浏览器正在使用哪个 AI。WPS / 飞书 / Notion 的客户端识别也不代表其中 AI 功能已启用。

## 高级排查流程

在侧边栏展开“高级排查”，或点击首页底部“其他工具连接有问题？”。

1. 在高级排查的诊断工作区点击“开始新诊断”，输入域名或 HTTPS URL，可以选择实际应用进程，并手动确认候选子进程。
2. 确认探测目标和观察时长。默认 60 秒，可选择 30 / 120 秒；诊断模式可比较直连与用户明确填写的 HTTP CONNECT / SOCKS5 代理。
3. 切换到目标应用复现问题，点击“标记错误时刻”，或延长观察。完成观察会开始探测；“取消诊断”停止后续工作并保留已有证据。
4. 在结论页核对规则、支持证据、未确认项与下一步。点击证据进入原始阶段详情。诊断器探测不等同于目标应用自身请求。
5. 手动复测目标应用，保存“成功 / 仍失败 / 不确定”。该记录属于用户声明，不自动升级为强证据。
6. 点击“导出报告”，预览 Markdown 或 JSON 的实际内容，然后在原生保存对话框中选择路径。默认隐藏目标、地址、进程标识、配置值与自由文本。

应用联网页面提供手动刷新的真实 TCP 快照。会话对比需要选定进程实例，先观察空闲基线，再点击“开始任务窗口”；完成后按 IP 与端口对比新增目标，不推断请求内容或恶意性。

## 实现与文档之间的选择

当前开发环境为 macOS，未配置 Rust。首版采用详细设计允许的 Electron 容器替代方案：Electron + React + TypeScript，探测及会话核心暂用 Node.js，而非技术文档推荐的 Tauri + Rust 原生核心。这是一项明确的实现差异，后续可替换独立的 `electron/core` 模块而保留界面和 DTO。

| 模块            | 当前实现                                                                                    | 范围                                                                         |
| --------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 进程与 TCP 采集 | macOS `ps` / `lsof`，Windows CIM / `Get-NetTCPConnection`                                   | 普通权限只读；实例键含本次系统启动时间、PID、创建时间；用户确认子进程范围    |
| 配置快照        | 环境代理变量、DNS、接口、时间；macOS 系统代理 / DNS / 默认路由；Windows 账户与 WinHTTP 配置 | 当前诊断器或账户配置，不声明目标应用实际配置                                 |
| 分层探测        | 系统 DNS、显式地址 TCP、CONNECT / SOCKS5、同一连接 TLS + HEAD                               | 证书验证开启；无认证、无重定向跟随；HTTP/1.1；目标根路径                     |
| 规则            | R01–R08，联网对比 R10                                                                       | 显示证据和缺口，支持等级为有限或不足以判断                                   |
| 数据库          | sql.js SQLite，完整镜像临时写入 + fsync + 原子替换                                          | 为免原生模块 ABI 依赖，未实现 Rust 单写线程、WAL 和大规模事件投影 / 分页架构 |
| 导出            | Markdown / JSON、白名单字段、预览哈希绑定、原生选路径                                       | 预览过期时拒绝导出；保存失败不报成功                                         |
| AI              | 本地规则解释                                                                                | 云端模型、凭据存储和外发确认流程尚未接入                                     |
| 增强采集        | 未实现                                                                                      | ETW、macOS Network Extension、UDP 远端流和逐进程字节统计明确为缺失能力       |

采集每秒一次，单会话上限 2,000 条连接观察，截断会累加丢失计数。只允许一个活动会话，每主机每分钟最多 6 次连接尝试，主动探测整体预算 30 秒。进程退出不自动加入同名新实例。基线与任务时长、快照覆盖和 CDN 地址变化都会限制对比结论。

数据库默认保存 7 天，可选择 1 / 7 / 30 天，目录位于 Electron 的本机用户数据目录（macOS：`~/Library/Application Support/Network Lens/diagnostics.sqlite`）。逻辑删除不承诺 SSD 物理安全擦除。数据库没有完整加密，不存模型密钥或应用认证头。

## 源码结构

```text
electron/
  main.ts           # 桌面窗口、受限 IPC、原生报告保存
  preload.ts        # 类型化白名单桥接，不暴露 shell / filesystem
  core/
    platforms.ts    # 平台检查状态、并发、停止和频率限制
    platform-probe.ts # 系统网络入口与失败后的补充探测
    validation.ts   # 目标和代理校验
    collector.ts    # 固定只读系统命令，无 shell 拼接
    probe.ts        # 显式分层探测、超时与取消
    rules.ts        # 本地确定性规则
    manager.ts      # 会话状态、快照与比较
    store.ts        # SQLite 持久化与恢复
    report.ts       # 白名单脱敏、报告与哈希
src/
  InstalledTools.tsx # 本机工具、组件与版本、官方适配草案与功能诊断入口
  FileProtection.tsx # 文件范围、独立策略、覆盖、自检提醒与审计报告
  shared/assistant.ts # 工具身份、策略、审计与受限接口
  shared/adapters.ts # 官方资料与适配发布门槛，当前全部为未实测草案
  ToolHome.tsx      # 默认 AI 工具体检、筛选、建议和 IT 反馈
  shared/platforms.ts # 固定平台目录和公开入口来源
  App.tsx           # 高级页面、诊断向导、证据 / 导出对话框
  shared/types.ts   # 前后端 DTO
  demo.ts           # 独立演示数据与行为
tests/              # 规则、隐私、持久化和受控协议测试
```

渲染器启用 sandbox、contextIsolation，关闭 Node integration。IPC 验证窗口来源及输入 Schema；不开放任意命令、文件读写或系统配置修改。日志和证据通过 React 文本渲染，拒绝远程窗口与未经批准的页面导航。参考 [Electron 安全建议](https://www.electronjs.org/docs/latest/tutorial/security)。

```sh

```

核心测试覆盖输入校验、IPv4 / IPv6 快照解析、八类规则及前提缺失、报告脱敏、SQLite 重启与中断恢复，并用本机受控服务器检验同流 TLS + HEAD、HTTP 429、HTTP CONNECT、SOCKS5、本地解析失败后的代理远端解析、代理 407、证书拒绝与取消。

## 平台目录维护

平台公开入口及官方来源记录在 `src/shared/platforms.ts`，核对日期为 2026-10-03。平台的后台域名可能变化，当前首版不声称完整覆盖服务依赖。飞书、WPS、Notion 等办公产品的入口可达性不能替代企业租户与 AI 后端检查。目录更新需同步核对官方来源与实际产品网络依赖。

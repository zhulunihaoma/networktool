# Gitee / GitHub 应用更新

设置 → 应用更新。当前版本从 Electron 读取，不再写死在界面中。

- 自动：同时检查两边，在成功返回的清单中选择较高稳定版本，默认 Gitee 下载；连接失败、停滞、HTTP 错误、返回登录网页或大小 / SHA-256 不符时改从 GitHub 下载**同一版本、同一系统和架构**。若一边检查失败，界面保留原因，不将失败说成最新版本。
- 手动 Gitee / GitHub：仅使用所选站点，选择保存到本地数据库；切源后重新检查。两边同版本同平台的文件名、大小或哈希不同则阻止下载。
- 显示当前版本、运行平台、检查时间、各源结果、发行说明、进度和失败切换记录。可取消检查 / 下载，退出应用也会取消；失败和取消会清理未完成文件。
- 下载到应用用户数据目录的 `updates/<随机目录>/`，通过大小和 SHA-256 完整性校验后提供“打开下载位置”。Windows 用户关闭应用再运行安装程序；macOS 用户退出应用再替换 `.app`。不自动执行安装程序或覆盖运行中的应用。
- 下载状态保存在当前进程中；重启后可重新下载，已完成文件保留，可从下载目录手动清理。不支持跨源断点续传，切换时从零重新下载。
- 浏览器演示不连接更新源或下载文件。

## 固定更新源

配置见 `updates/sources.json`。两个仓库 `master` 分支的 `updates/stable.json` 是更新入口，安装包放在各自 `v<版本>` 发行版。代码推送本身不会生成或上传安装包。

初始清单为 `release: null`，代表尚未配置可下载发行版，避免将旧安装包冒充本次源码构建。请将本功能发布到两个仓库后再实测清单访问；公开仓库和附件必须允许未登录 HTTPS 下载。Gitee 若返回登录或反爬页面，客户端会提示并在自动模式尝试 GitHub。下载重定向仅允许固定的 GitHub / Gitee 分发域名。

## 发布一次新版本

以下以未来的 `0.4.0` 为例，先确定版本号并更新 `package.json` 与锁文件，再构建，不能复用旧版本安装包。

1. `npm ci && npm test`，macOS 运行 `npm run package`；Windows 运行 `npm run package:win`。macOS 现在同时生成 `.app` 目录和可下载 ZIP。需要分别构建各架构并确认运行；清单中只填写真正构建并验收的平台。
2. 收集安装包、编写纯文本更新说明，用以下命令生成清单（路径替换为实际文件）：

   ```sh
   npm run release:manifest -- --version 0.4.0 \
     --asset win32-x64 "release/Network-Lens-0.4.0-win-x64.exe" \
     --asset darwin-arm64 "release/Network-Lens-0.4.0-mac-arm64.zip" \
     --notes release/notes.txt
   ```

   输出默认 `release/stable.json`。脚本逐文件计算大小和 SHA-256，并生成两边的固定版本地址；不读取上传凭据，不访问网络，不自动发布。可用 `--output` 指定暂存清单位置。

3. 在 Gitee、GitHub 分别建立 `v0.4.0` 发行版，上传**同一批字节和相同文件名**的安装包。Git 镜像同步不替代附件上传。
4. 退出登录后实测所有下载地址；核对大小、哈希和安装行为。确认两边上传都完成后，将生成的 `release/stable.json` 复制到 `updates/stable.json`，提交并推送两边 `master`。后发布清单可避免客户端看到尚未上传的文件。
5. 用上一版应用验证自动、手动源、断网、下载失败、取消及实际安装。更新 UI 不会将只同步源码视为可用安装更新。

当前安装包尚未配置发布签名。HTTPS 与 SHA-256 用于传输和文件完整性验证，清单随仓库发布，不能防御仓库账号被盗后的恶意替换。当前流程因此保留用户手动安装。后续接入系统代码签名、公证和独立签名验证后，再考虑无人值守安装。

## 本地验证

```sh
npm test
npm run build
node scripts/verify-app-updates.mjs
node scripts/verify-update-startup.mjs
```

单元测试使用注入网络和临时目录，覆盖版本选择、镜像不同步、下载中断及切换、校验失败、取消、并发与重定向限制。桌面验收使用真实 Electron / preload / IPC 与合成 HTTPS 响应，不访问真实私人数据，不上传或发布。

开发时使用 `npm run dev`：主进程和 preload 的依赖变化会重新编译并重启 Electron，前端组件继续由 Vite 热更新。启动时等待两个 Electron 入口编译成功后才打开窗口；后续编译失败保留上一份可运行实例。`npm start` 也会先编译 Electron 入口。若连接更新服务失败，界面会显示当前构建版本与明确的未连接状态，不再一直停在“读取版本中”。

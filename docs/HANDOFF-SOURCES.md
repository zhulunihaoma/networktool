# 本机会话来源识别与接力

任务接续会自动识别本机工具，并提供“识别本机工具”按钮。安装身份复用本机应用识别模块；会话可用性独立检查，不把残留配置目录当成已安装程序。WorkBuddy 的实际 macOS bundle ID 和 ZCode 已补入安装识别目录。

## 来源

| 来源 | 列表、标题和项目 | 正文 |
| --- | --- | --- |
| OpenCode | 原有 CLI 最近 30 条 | 原生导出 |
| Codex | 原有官方 App Server 分页及项目索引 | 官方历史分页优先 |
| Claude Code | 原有本地最近 30 条 | 用户请求和可见回复 |
| WorkBuddy | `~/.workbuddy/workbuddy.db`，自定义标题优先，排除删除、隐藏和后台自动化记录 | `projects` 下当前会话 JSONL，忽略工具和推理记录 |
| ZCode | CLI SQLite 主会话，客户端索引中的改名、删除、归档优先 | SQLite 中可见消息的文本片段，忽略合成输入和隐藏提醒 |
| WisCode | 独立的 Claude、Codex 引擎配置，按引擎和会话 ID 隔离、去重 | 复用各引擎读取器；分页正文不可用时不以旧日志冒充 |
| DeepSeek Harness | 原生会话缓存中的标题、目录、最近请求时间，排除空会话 | 完整压缩日志，逐帧解压 Zstandard 追加日志，忽略流式镜像、推理和注入上下文 |
| 极库 Copilot Code | VS Code 与独立扩展存储中的任务；标题取首条用户请求 | 已提交 UI 消息和用户反馈，忽略 API、工具、推理、图片和重复完成事件 |

五个新来源均先按全量元数据筛选项目和搜索，再以每页 50 条加载。分页游标绑定当前筛选范围，导入只接受已加载 ID；导入前重新检查来源记录和当前正文路径。

极库 Copilot Code 的上述存储没有提供可靠的工作区字段，因此显示“未关联项目”，接力时提示确认目标工作区，不根据引用文件猜目录。WisCode 管理的聊天不会混入原生 Codex 或 Claude Code 标签。DSH Desktop 和 DeepSeek Harness 共用 `.dsh` 数据目录，只列为一个来源。

仅识别安装、尚未接入聊天读取的工具显示在“其他已识别工具”。已安装的 VS Code 等可以作为复制后粘贴的接力目标；只有配置、没有确认安装或聊天的 Gemini 不会假装成可用来源。

## 读取边界

- 固定来源目录；不读取凭据文件，不跟随正文符号链接，不执行历史中的命令或附件地址。
- SQLite 使用原生只读连接，识别已提交 WAL；不迁移、修复或重写来源数据库。
- 日志读取及解压后均限制 8 MB，正文限制 5000 条消息、120000 字符；损坏或超限明确报错，不返回截短正文。压缩日志尾部损坏也不能只导入前面几帧。
- 已知凭据和邮箱脱敏；预览仍需用户检查。用户核对后复制全文，再到目标工具粘贴、发送；应用不自动启动任务。
- 当前本机 macOS 已验收。其他系统的工具发现和各产品实际数据目录仍受既有平台覆盖限制。

## 验证

```sh
npm run build
npm test
node scripts/verify-extra-handoff-workspace.mjs
node scripts/verify-extra-handoff-workspace.mjs --live
node scripts/verify-handoff-workspace.mjs
node scripts/verify-codex-workspace.mjs
```

默认桌面验收使用隔离 HOME、带 WAL 的合成 SQLite、逐行多帧 Zstandard 日志，测试五个来源的识别、导入、目标选择、预览脱敏和实际剪贴板内容一致性，最后恢复原剪贴板。`--live` 只读抽查本机列表和正文，输出数量与长度，不复制、不发送私人内容。

2026-10-21 本机抽查：WorkBuddy 51 条、ZCode 1 条、WisCode 90 条、DeepSeek Harness 7 条、极库 Copilot Code 121 条，五种均成功导入真实可见正文。其中一条 WorkBuddy 会话正文超过 120000 字符，被明确拒绝；抽查另一条后成功。数量仅代表当时本地可见历史，不代表任务数或完成状态。

## 可恢复附件接力

编辑接力说明时自动识别所选会话的附件记录，默认关闭“同时打包附件”。关闭时继续原有文字复制；开启后选择附件、确认原内容，再选择保存目录导出 ZIP。导出成功后可复制交接说明与实际附件包路径；此操作不会向目标客户端上传附件，用户需要在目标工具选择附件包或解压后读取。

附件提取只处理用户消息中明确的结构化附件，不扫描正文路径、工具输出或整个工作区：OpenCode 的 file 数据 URL、Codex 官方历史中的 image/localImage（兼容旧日志中的 input_image）、Claude/WisCode Claude 引擎的 Base64 图片或文档、WorkBuddy blob、ZCode artifact、DSH 持久化对象及极库 Copilot Code 的用户图片。WisCode Codex 引擎复用 Codex 读取器。来源仅保留普通文件路径或远程 URL 时显示“需手动补充”，不会把当前文件冒充历史快照，不自动联网下载。

- 状态区分可打包、文件缺失、格式未支持、读取失败、扫描未完成。未知不等于无附件。来源结构未确认时，即使补充了本地文件也保持“不完整”标记。
- 可单独勾选、全选和取消全选；“补充文件”通过原生文件对话框选择当前本地文件，不自动替换缺失记录。
- 有缺失或未知内容时必须明确确认仅导出可用部分；清单保留未携带附件及原因。
- 包含 `handoff.md`、`manifest.json` 和 `attachments/`，按 SHA-256 合并相同内容，保留每条消息与实际文件的对应关系。清单完整性仅指已识别附件范围，不保证来源保存了全部历史信息或上传原件。
- 原附件不做脱敏，界面单独提示并确认；可能保存的是来源工具压缩/转换后的图片。文档只有提取文本时不重建原文件。
- 每个附件最多 16 MB，单次扫描合计最多 64 MB、128 条记录；超限明确标记，不能静默当作完整导出。导出使用扫描时捕获的内容，重新扫描、补充或切换来源后旧确认失效。
- ZIP 使用唯一文件名、新建写入和私有文件权限；取消保存不导出、不复制，写入失败可以重试。文件选择及保存路径由主进程的原生对话框提供。

附件验收：

```sh
npm run build
npm test
node scripts/verify-handoff-attachments.mjs
```

该脚本在隔离 HOME 中验证八种来源，并通过真实 Electron IPC、弹窗和系统剪贴板验证附件勾选、手动补充、部分导出确认、取消保存、内容去重和纯文字回退。独立 Python ZIP 实现校验 CRC、文件哈希、中文文件名和解包内容。此验收不调用模型，也不代表附件已自动送达其他客户端。

# VPN 与海外 AI 服务网络访问检查和处理方案

本文面向日常办公用户，用来判断“平台本身访问限制、VPN 未生效、网络路径配置错误、VPN 本机代理端口冲突”几类常见问题。它是人工排查指南，不会自动修改网络设置、结束进程、切换 VPN 地区或代替公司 IT 的批准。

## 先看检查结果

Network Lens 逐个平台显示系统网络、补充直连和补充代理的结果：

- **入口可连接 / 收到 HTTP 响应**：当前这条网络路径已经到达平台入口。登录、账号权限、聊天生成、上传和客户端专用 API 仍要在平台本身验证。
- **访问受限 / 平台拒绝**：网络请求到达平台，但平台返回拒绝。不要把它当成 VPN 端口或断网问题；查看平台地区与组织政策、企业网关规则，必要时联系管理员。
- **网络连接失败**：此次路径没有连接到入口。根据界面列出的路径、阶段和错误码继续检查 DNS、代理、TCP 或 TLS。
- **检测未完成**：诊断程序没有拿到足够证据。这不是“网络肯定不通”的结论；稍后单独重测一次。
- **TLS 已连通、入口未响应**：安全连接建立了，但平台没有返回 HTTP 页面。常见于入口不接受此类只读 HEAD 检查；用浏览器实际打开验证，不要据此判断平台完全不可用。

系统路径、直连与代理路径可能不同。例如“系统路径失败，补充直连可访问”表示系统当前采用的路由/代理与直连结果不同；平台卡片会保留两者各自的结论，不以一条路径覆盖另一条。

## 按顺序排查

### 1. 确认服务在当前地区是否可用

先在浏览器打开对应平台官网，并查看平台自己的国家/地区、企业租户和服务状态说明。若平台明确不在你所在地区提供服务，或工作账号受组织政策限制，应选择本地区可用的公司批准工具或联系管理员；不要通过伪装地区规避服务条款、组织政策或法律要求。

海外 AI 服务的地区政策可能按产品、账号类型和组织所在地不同而变。提交工单前请检查平台官方页面，例如 [OpenAI 支持地区](https://help.openai.com/en/articles/7947663-chatgpt-supported-countries)、[Anthropic 支持地区](https://www.anthropic.com/supported-countries)、[Google Gemini 可用地区](https://support.google.com/gemini/answer/13575153)。以平台当时的官方说明和公司政策为准。

### 2. 判断是否需要 VPN

1. 确认这是公司批准或个人合法订阅、且明确允许访问目标服务的 VPN / 安全访问工具。
2. 查看公司 IT 或服务管理员给出的目标服务网络要求；不要仅凭“海外平台”就假设所有流量都应经 VPN。
3. 在获准的网络环境中，查看 VPN 客户端是否显示已连接、连接到哪个组织批准的出口/地区，以及是否报告 DNS、认证或策略错误。
4. 如组织允许比较，可先记录 VPN 关闭/开启时的平台入口结果；每次只改变一个状态，并恢复到公司要求的连接方式。受管理设备不要自行断开公司 VPN。
5. 如果系统路径和补充直连结果相反，重点检查 VPN 的全局/分流路由及 DNS 策略，并把两条结果交给 IT。部分应用使用自己的代理设置，因此浏览器、桌面客户端和系统代理可能走不同路径。

### 3. 检查 VPN 是否真正承载目标流量

- 如果 VPN 客户端显示已连接，但目标平台超时，确认客户端策略是否包含该服务的域名和 DNS；分流模式可能只接管企业资源，或反过来只让特定应用走隧道。
- 如果 DNS 解析失败或 IP 家族表现不同，把 Network Lens 的 DNS / TCP / TLS 阶段和 IPv4、IPv6 路径结果交给 IT。不要手工改系统 DNS、路由表或证书信任设置。
- 如果浏览器能打开而桌面 AI 客户端失败，优先比较应用自己的网络/代理配置及企业允许的客户端策略。Network Lens 检查公开网页入口，不代表客户端后端全部可用。
- 若公司配置了全局 VPN、安全代理或终端防护，不要叠加第二个 VPN/代理来“试试看”；多个隧道常造成路由、DNS 和端口冲突。

### 4. 只读检查本机代理端口是否有人监听

只有在 IT 或 VPN 客户端明确提供“本地代理地址和端口”时才做本项。将 `<端口>` 替换成客户端显示的数字；这些命令仅读取监听状态，不会结束进程或更改配置。

macOS：

```sh
lsof -nP -iTCP:<端口> -sTCP:LISTEN
```

Windows PowerShell：

```powershell
Get-NetTCPConnection -State Listen -LocalPort <端口>
```

Windows 官方命令说明：[Get-NetTCPConnection](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection?view=windowsserver2025-ps)。

- **查到监听进程**：核对进程是否为公司批准的 VPN / 代理客户端。若是其他软件占用了客户端要求的端口，记录进程名交给 IT 或软件管理员处理；不要自行结束未知进程。
- **没有监听进程**：VPN 的本地代理组件可能没有启动，或实际监听在另一个地址/端口。让管理员核对客户端运行状态与配置。
- **地址族不匹配**：`127.0.0.1` 是 IPv4 回环地址，`::1` 是 IPv6 回环地址。监听地址不同可能导致客户端报“代理拒绝连接”；将端点地址和监听输出交给管理员，不要自行猜改。
- **端口可监听但仍无法连接**：监听只证明本机端口有人接收连接，不证明隧道、认证、目标路由或平台地区策略正确。

不要把完整代理地址、用户名、密码、访问令牌、VPN 配置文件或出口 IP 发到公开工单或聊天中。

## 交给 IT 的最小信息

提供发生时间（含时区）、系统版本、公司/家庭网络类型、VPN 客户端显示的连接状态、该平台的系统/直连/代理结果、失败阶段和错误码，以及浏览器是否能打开平台官网。描述 VPN 出口地区时使用管理员提供的地区名称即可，不必附出口 IP。复制 Network Lens 的“结果给 IT”内容前，检查并移除你自行补充的账号或内部信息。

## 管理员处理建议

按顺序确认：服务官方地区/组织政策 → 用户所在网络与获批隧道 → 分流路由和 DNS → 客户端代理地址、绑定族和端口监听 → 企业防火墙或安全网关策略 → 平台返回的状态码。每次更改前记录原状态，先在一台受控设备上验证，按组织变更流程回退或扩大范围。Network Lens 不应自动切换出口地区、关闭证书验证、停止冲突进程或写入 VPN 配置。

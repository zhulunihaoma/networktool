# 参赛策略与冲分打法（360AI盒子）

> 本文档基于对仓库的完整扫描（约 4.5 万行代码、344 个单元测试、48 个测试文件、26 个 Playwright 验收脚本）给出参赛策略建议。
> 核心判断：**这不是一个"网络工具"，这是一个"AI 工具安全治理工作台"。安全中心是唯一够格冲击冠军的资产。**
> 本文档只提建议，不修改任何代码。

---

## 一、项目的真实底牌（扫描结论）

### 王牌资产（真实现、非 mock）

1. **事前拦截（guard）**
   - 通过 PreToolUse 钩子接入 Codex、Claude Code、ZCode、OpenCode、DeepSeek Harness 五个 agent 框架；
   - 9 条文本规则：保护分支、破坏性命令、远程执行、凭据读/写、提权、受保护路径写入、DNS 外发、输入上限；
   - 配置写回带备份、UUID token、marker 合并、原子临时文件 + rename、失败回滚；
   - 关键点：**这是"真保护"，不是界面壳。**

2. **防篡改审计链**
   - `events.jsonl` 每行 sha256 链式哈希 + 跨进程文件锁 + 轮转；
   - 现场篡改一行日志、链断裂被检出的 demo，是全场无法复制的"哇"时刻。

3. **自检模拟（8 个攻击载荷走真实 guard 二进制）**
   - "演示：快速产生真实防护数据"入口，可在现场生成真实拦截证据；
   - 不需要编数据，这是拿名次的作弊器。

### 支撑层（真实逻辑）

- 技能中心：18 个目标工具互拷、逐文件审核、兼容转换、源/目标哈希校验、删除到回收站；
- 多 Agent 任务接续：9 类来源、zstd 上下文归档、脱敏清洗、附件安全校验；
- 记忆工作台：Markdown 只读发现 + 显式引用图；
- 顺序排查 triage：R01–R08 证据规则、分层探测（DNS → TCP → CONNECT/SOCKS5 → TLS+HEAD）；
- 工具识别：22 类工具、macOS bundle/CLI/NVM/fnm、主进程冻结工具身份防前端伪造；
- 模型端点体检：20 个端点匿名探测、401 语义正确解释；
- Electron IPC 卫生：sandbox、contextIsolation、zod 输入校验、窗口来源验证、拒绝任意导航。

## 二、会拉下第一名的五个风险（按致命程度排序）

1. **文件策略模块是"假防护"**
   - 仓库自述 `canBlockToolAccess: false`，只能审计助手自己的策略，拦不住任何第三方 AI 工具；
   - 评委若为安全背景，三句话问穿；
   - 答辩原则：**绝不把它讲成防护能力**。要么不讲，要么只讲成"策略台账与脱敏审计报告"。

2. **产品命名一致性（已统一）**
   - 产品名称已统一为“360AI盒子”，同步到 README、运行窗口与安装包；仓库目录保留 `networktool`；
   - 后续演示与发布资料继续使用这一名称，避免评委混淆产品身份。

3. **仓库卫生**
   - 43 个文件未提交、仅 6 个 commit、无 tag；
   - release 安装包仍是旧构建，与当前代码对不上；
   - 若评委查看仓库，这是明显减分项。

4. **主题漂移风险**
   - 若比赛主题是"网络工具"，约 80% 的新代码（安全、接续、记忆）显得跑题；
   - 若主题是"AI / 安全 / 效率"，网络诊断只是边角料；
   - **主题决定主打牌，需根据比赛规则确定。**

5. **发布形态**
   - 零签名 / 公证；Windows 未实机验收；
   - 评委现场装机请用 mac-arm64 zip 演示，避开 Windows 安装器。

## 三、冲第一的打法：一个故事，一条主线，五分钟

评审的本质：**评委记不住 8 个功能，只记得住 1 个故事 + 1 个 wow 时刻。**

### 主打故事

> 普通办公用户的"AI 安全体检台"——事前拦截、事中留证、事后追溯。

- 一句话定位："AI 助手进公司之后，没人管它们在你电脑上干什么。这个工具替你看住它。"
- 目标人群：公司已经引入 AI 编程/办公工具、但没有安全团队覆盖的普通用户。

### 五分钟 demo 剧本

1. **体检**（0:30）：一键检查，得分从 62 → 100 的过程；
2. **拦截**（1:30）：模拟 AI 助手尝试删除主分支 / 读取 SSH 私钥 → 被 guard 拦下，证据页显示命中的规则；
3. **wow 时刻**（1:00）：现场篡改一行事件日志 → 防篡改链报警；
4. **追溯**（1:00）：历史扫描（"查杀"）找出过去 3 次危险操作，导出脱敏报告；
5. **收尾**（1:00）：一句话带过网络诊断 + 任务接续（"顺手解决了 AI 工具连不上、任务怎么转给另一个助手"）。

### 诚实即护城河

- 仓库最强的气质是"证据优先、不吹做不到的"；
- 答辩专门放一页"真实能力 vs 明确未实现"，评委对敢标注边界的参赛队信任度翻倍。

## 五、预判评委刁钻问题与标准答案

1. **"你的文件策略能拦住 AI 工具读文件吗？"**
   → 不能，如实说。它是策略台账 + 审计报告；真正的拦截在 guard 模块（针对 coding agent 的命令）。把战场拉回安全中心。

2. **"规则是正则文本匹配，能绕过吗？"**
   → 承认是第一道防线，配防篡改审计链兜底：被打穿也有证据。展示 fail-open 设计，说明"绝不搞坏用户的 agent"。

3. **"和 360 自家安全产品比，你算什么？"**
   → 差异化：面向 AI agent 命令级的事前治理 + 多工具治理台，不是杀毒，不抢它的活。

4. **"为什么不用 Tauri + Rust？"**
   → 开发环境限制下的替代方案；核心逻辑集中在 `electron/core` 独立模块，接口与 DTO 分层，可替换而不改界面。

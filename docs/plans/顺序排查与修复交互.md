# 顺序排查与修复交互（0.3.0）

首页新增“连接异常，或经常重连？”入口，默认选择 Codex，也可选择现有 14 个平台。用户点击“按顺序排查”后，逐项显示等待、检查中、通过、需要处理、需要确认、检测未完成或未执行。排序依据是逻辑依赖与本次证据，没有故障概率百分比。

## 检查和推荐顺序

| 顺序                  | 真实检查                                                                                        | 结果边界与建议                                                                                            |
| --------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 1. 基础网络           | 查询非回环、非链路本地的接口地址                                                                | 有地址不代表能访问互联网；未发现可用地址时，后续主动检查标记未执行，先打开网络设置                        |
| 2. 代理与 VPN 入口    | Chromium 为目标选择的系统代理；若是显式代理，尝试该端点 TCP；本地代理尝试读取监听进程名称       | DIRECT 不代表没有 VPN；端口接受连接不代表隧道正常；监听进程不匹配必须人工核对，不自动认定端口冲突         |
| 3. 域名解析           | 系统解析器查询公开入口主机，记录 IPv4 / IPv6 地址数量                                           | 解析失败但系统/代理入口已经响应时，不将本机 DNS 当作应用故障根因，优先复现持续会话                        |
| 4. 安全连接与平台响应 | 无凭据 HEAD 请求；系统路径失败时沿用补充分层探测                                                | 保留路径差异、证书错误与 HTTP 结果；401 不证明用户登录失效；官网入口不等于真实 AI 请求                    |
| 5. 持续使用与重连观察 | 用户主动开启 60 秒观察；每秒尝试 TCP 和接口快照，每 10 个有效样本重新查询系统代理；标记错误时刻 | 仅限起始识别到的已知进程实例；不自动跟踪同名重启实例。TCP 存在或消失不证明 WebSocket / 流式响应成功或中断 |

首先推荐处理本次已观察到的基础网络、代理端点、DNS 或入口异常；没有明确入口异常时建议复现观察。采集错误不当作“没有连接”。检查停止后丢弃迟到结果。公开入口检查至少间隔 30 秒，同一入口主机的 Codex / ChatGPT 共用顺序排查限频。

Codex 使用 ChatGPT 公开入口作为连通性参考，识别 Codex / codex 及已知 Helper 名称；未验证 Codex 实际模型、认证服务或任务请求，也未读取 Codex 日志或账号凭据。自动识别到的同名进程可能属于多个窗口或账号，不归属到某条聊天。

## 处理按钮

| 按钮                                  | 实际操作                                                 | 完成后的呈现                                                 |
| ------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------ |
| 打开网络 / 代理 / 日期与时间设置      | 主进程使用固定系统设置 URI，macOS 和 Windows 分别映射    | 提示已请求打开设置，等待用户按建议处理；不自动更改配置       |
| 重建检测连接                          | 只清理 Network Lens 自身 Chromium 解析缓存并关闭自身连接 | 明确说明原 AI 工具未重启，不宣布已修复；有其他检测时拒绝执行 |
| 打开平台入口 / 查看官方服务状态       | 打开预置官方 URL；服务状态入口目前针对 OpenAI            | 需用户在原工具中核对登录与真实任务                           |
| 处理后重新检查                        | 对同一目标重新运行顺序排查                               | 比较先前异常项目是否通过，不将入口通过等同于应用修复         |
| 我在原工具确认已恢复 / 原工具仍有问题 | 保存本次排查内的用户声明                                 | 单独标识“用户复测记录”，不升级检测证据                       |
| 复制排查结果给 IT                     | 复制本次结论、阶段、脱敏依据及观察数量                   | 不包含内部接口地址、网络签名、原始代理端点或账号凭据         |

操作通过类型化 IPC 白名单执行，绑定当前排查 ID 和适用建议；未知操作、不适用操作和过期报告拒绝执行。系统设置无需在渲染器中传入 URL 或命令。

## 不自动执行的操作

VPN 出口切换、系统 DNS / 路由 / 证书变更、结束监听进程、重启 AI 客户端、注销登录或重试真实付费生成任务均未实现为自动修复。VPN 的人工处理流程参见 [VPN 网络访问检查和处理方案](VPN-网络访问检查和处理方案.md)。

## 本版限制

顺序排查在主进程内暂存，应用退出后不保留；可复制脱敏结果给 IT。60 秒观察记录网络接口/地址、系统代理和选定起始进程的变化，未采集 UDP / QUIC、TCP 重传、精确断连事件、应用日志或加密请求内容。不输出“持续连接正常”或“VPN 一定掉线”。

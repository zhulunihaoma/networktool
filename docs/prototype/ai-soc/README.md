# AI 行为安全 · 事件中心原型

单文件 HTML 原型，浏览器直接打开 index.html 即可。不依赖构建，不读写任何本地配置，不连接任何服务 —— 全部数据为演示数据，页面带有「演示数据」标识。

配套方案文档：docs/plans/A方向-AI行为接入安全平台-实施方案.md

## 设计目标

现有 docs/prototype/security-center/ 讲的是「单机上的防护能力」；本原型讲的是防护结果出机器之后长什么样，即公司安全平台侧的视角：

- 散落的告警如何合并成一条可处置的事件
- AI 行为如何纳入既有的日志分析 / 分类分级 / 异常行为三条产品线
- 处置动作如何回落到终端形成闭环

复用 security-center 的设计 token（配色、字体、圆角、阴影），视觉上属于同一产品的延续，而非另起一套。

## 页面

| 页签 | 对应方案章节 | 重点表达 |
| --- | --- | --- |

## 交互

- 顶部页签切换，左侧同名子菜单同步高亮；侧栏子菜单也可直接跳转。
- 事件链：点击左侧事件切换右侧详情；按 critical / high / medium / low 筛选。
- 事件详情：时间轴展示合并前的每一条原始告警，底部是处置动作，点击后标记「已下发 · 等待回执」。
- 外送页：开关可切换（仅切换显示，不写 localStorage，不改任何真实配置），支持键盘 Enter / Space。
- 所有提示均为 toast，不产生真实文件、不发真实请求。

## 与真实实现的差距

- 事件、告警数量、资产清单、时间戳全部是构造数据，不对应任何真实机器。
- 合并规则在文档里给了判定条件（R1–R4），原型只演示结果，不含合并引擎。
- 外送通道、拉取通道、处置回执均为界面示意，没有网络实现。
- 分级规则的「平台下发」是设计目标，当前无对接。
- 图表为手写 SVG，数据写死在脚本里，不反映真实趋势。

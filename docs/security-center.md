# 本地智能体安全中心

左侧选择 **安全中心**。数据和守卫脚本默认保存在应用用户数据目录的 `security/` 子目录，检查过程在本机执行。

## 使用流程

1. 在“概览”点击“立即体检/重新体检”。体检在概览页原地进行，检查步骤由后台逐组真实上报（凭据文件权限 → Codex 审批/沙箱/MCP → 各工具配置 → 常见凭据位置 `.ssh`/`.npmrc`/`.netrc`/`.git-credentials`），完成后显示读取文件数、问题数及评分变化，不会跳转。下方“待处理问题”按高、中、低风险排序，每项都有一个处理按钮：
   - **一键修复**：凭据文件权限过宽，先展示要修改的文件，确认后改为仅当前用户可读写。多项时提供“一键修复 N 项”。
   - **信任此防护 / 开启防护 / 修复防护**：工具防护未生效，直接在此处理，与“防护开关”使用同一流程。
   - **打开文件位置**：需要人工判断的配置（如 Codex 关闭审批、完全访问），在访达中显示文件；“详情”里给出逐步修改方法，改完后点“重新体检”。
   - **暂不处理**：确认是有意设置时可选择，不再扣分；可在列表底部“查看已暂不处理的项目”中恢复。
   点击“评分依据”可展开加扣分明细：基础 80 分，按权限、密钥、来源、联网、完整性五类合并，每类只按最高风险扣一次（高 16 / 中 8 / 低 3），同类数量不累加。完成且实际读取到文件的体检加 5 分（有未读文件则不加），非空事件链校验通过加 5 分，支持工具的防护接入比例加 0–10 分（向下取整）。最终限定 30–100 分，下限调整单独列出，30 分不代表风险消除。未检查不视为通过；已暂不处理的当前问题不参与分类扣分。防护状态实时更新，已开启的不再提示重复开启。评分历史只展示本版规则生成的快照，旧记录保留在文件中但不混用。首页的“检查项与覆盖范围”分别展示配置、防护、历史复核入口和实际检查范围。
   **防护数据看板**：评分环下方展示“持续防护天数 / 累计检查 / 累计拦截 / 今日拦截”四个汇总数字，以及近 30 天检查与拦截趋势图、评分历史折线（每次体检记录一个真实快照）、按规则和按工具的拦截分布、处理记录（开启防护、修复、信任、暂不处理等操作的时间线）。所有数字由本地事件链聚合而来，没有手工数据；空数据时展示引导语而不是空白图。
2. “防护开关”默认开启：应用每次启动时会自动为本机已安装、且支持执行前拦截的工具写入防护，无需逐个点击。写入只合并本应用自己的钩子条目，保留工具原有配置，并在修改前做时间戳备份；任一工具写入失败只跳过该工具，不影响启动和其他工具。手动“关闭”过的工具会被记住，默认开启不会把它重新打开。已开启的工具也可在这里查看、自检或关闭。Codex 显示待信任时，直接点击本页 **信任此防护**；工具通过 Codex 本地接口保存并确认信任，无需在 Codex 输入命令。保存后重新打开 Codex 会话加载，其他工具也需重启会话。
   - 如需完全关闭默认开启，点击“关闭默认开启”；也可用环境变量 `NETWORK_LENS_AUTO_PROTECT=0`（或旧名 `NETWORK_LENS_NO_AUTO_PROTECT=1`）启动本次不自动执行。两者都只影响“自动写入”，不会删除已有防护配置。使用 `NETWORK_LENS_DATA_DIR` 的隔离配置（测试、便携运行）不会自动写入真实工具配置，该限制在服务层生效，页面“立即执行”也无法绕过；只有在隔离 home 与显式 `NETWORK_LENS_AUTO_PROTECT=1` 同时满足、或正常启动时才写入。
   - 自动开启在窗口打开前执行；页面上的“立即执行”可重试。结果按“已开启 / 已是启动状态 / 跳过 / 失败”分别计数。
3. “操作规则”顶部的**重点保护清单**完整展示敏感文件与后缀（红色）、保护分支（紫色）、保护路径（蓝色）和额外命令（橙色），并显示对应规则开关状态。点击“编辑清单”修改，统一点“保存防护规则”生效；未保存时明确标记为草稿。敏感路径支持 `~`、`$HOME` 与单层 `*` 通配（如 `~/secrets/*.pem`），目录匹配覆盖其子文件；额外命令按每段命令的开头及参数边界匹配，不区分大小写，复合命令会分段检查。下方可选择保护项目，填写项目相对路径和额外保护分支。全局规则作用于已加载防护钩子的工具，项目规则增加保护；对应开关关闭或存在项目例外时不会拦截。保存后守卫在下一次操作读取新配置，无需重新接入；首次接入、修复或信任后仍需重新打开工具会话加载钩子。
4. “安全事件”以 **AI 工具的一次操作尝试**（执行命令或读写文件）为一行，数据来自开启防护时注册到各工具里的执行前钩子，也就是内置探针，无需另外安装。页面顶部显示各工具探针状态（最近上报时间 / 已接入待重开 / 待信任 / 未接入），列表分为：
   - **敏感事件**：真实拦截和检查出错；
   - **全部 AI 操作**：拦截、放行及出错；
   - **本工具记录**：体检、规则自检、回溯扫描发现、防护设置、配置变化和**处理动作**（开启防护、修复、信任、暂不处理等），不属于 AI 操作，单独列出。
   列表支持按工具筛选、按日期过滤和分页（每页 50 条）；右侧“拦截通知”开关可在真实拦截发生时弹出系统桌面通知（默认开启，仅本机保存偏好）。每行用一句话说明“哪个工具在哪个项目想做什么、结果如何”，展开后显示调用方式、项目目录、命中规则及其保护的数据。右侧“保护了哪些数据”按规则汇总真实拦截次数（密钥与凭据、发布分支、Git 钩子等），点击即可筛选，敏感数据作为第二个维度。“模拟一次拦截”用已安装的检查程序运行 8 个样例（推送 main、读密钥、下载即执行、递归删除、强推、读 SSH 私钥、写 Git 钩子、一条正常命令），只做判定、不执行命令，结果计入“本工具记录”，不计为真实拦截。对于真实拦截，可选择“以后在这个项目允许”添加项目例外；例外只匹配该项目目录及该规则，可在操作规则中移除。
   不做系统级探针：需要管理员权限和内核扩展，误报和性能开销较大，也无法分辨操作是否来自 AI。钩子只在 AI 工具调用时运行，能准确对应工具、项目和操作；代价是未接入的工具、关闭钩子或绕过工具直接运行的程序不会被记录（见“已知限制”）。
5. **回溯扫描**（“查杀”）：只读扫描本机已保存的 AI 工具会话记录（Codex/Claude/ZCode/OpenCode/WisCode/DSH 的会话目录），找出历史会话中的可疑线索——读取密钥、管道执行、强制推送、明文密钥粘贴等。限额：每来源最多 120 个文件、总计 500 个文件、单文件 256KB，超出标记“仅扫描了最近的一部分”。历史命中独立展示，不进入当前问题或扣分，也无需通过“暂不处理”恢复分数。按风险种类给出核对执行结果、检查文件改动、轮换已泄露凭据等复核建议，不再统一要求开启防护。解析可识别的命令载荷，跳过会话元数据、命令说明和工具输出，同会话同证据去重；证据先脱敏再截取。未识别的会话格式不视为通过。扫描不会启动任何 AI 工具，不读取会话内容之外的东西。回溯发现同时记入“安全事件 → 本工具记录”（来源“会话发现”），与真实拦截区分。
6. **安全报告**：近 7 天防护活动摘要——被检查的 AI 操作数、拦截数、体检次数、周内评分变化、趋势图、本周做过的处理、累计拦截最多的工具与当前状态。数据全部来自本地事件记录与体检快照聚合，可导出完整 Markdown 报告。
7. MCP 导入前把 JSON/JSONC 配置粘贴到“安装前检查”。页面展示启动命令、外部地址和风险，支持复制脱敏配置；它不会自动安装 MCP 或执行启动命令。Skill 的检查集成在 Skill 中心的复制预览中，高风险复制须单独勾选确认。
8. “变更巡检”顶部说明用途、典型变化和三步操作：首次点击“建立配置基线”，以后安装插件、导入 MCP 或修改模型入口后，点击“检查配置变化”。页面保留上次检查结果，显示基线时间、检查时间及新增/变更/移除数量，可按工具筛选、展开或收起分组，并查看来源路径；文件摘要默认收起，避免将摘要误当成配置内容。没有变化时明确提示无需更新基线；没有配置时给出检查路径的引导。确认所有变化符合预期后，点击“将当前配置设为新基线”，在确认框了解替换比较基准的影响后更新（会重新读取当前配置，不修改 AI 工具配置）。无法完整读取时保留原基线与上次成功结果，显示错误和重试入口。
9. 任务接续时，凭据类附件会被拒绝打包，文本附件中的常见凭据会在导出副本中脱敏；源文件不变。

概览页底部“演示：快速产生真实防护数据”用本机真实检查程序跑 8 个典型场景（全部标注为自检，不计入真实拦截），适合第一次使用或演示时快速看到看板与事件流的效果。

## 接入和验证范围

| 工具             | 接入方式                                       | 验证证据与使用条件                                                                  |
| ---------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------- |
| Codex            | 用户级 `PreToolUse`                            | 已用隔离配置及真实 CLI 验证受保护分支推送被拒绝；支持在安全中心直接信任，仅授权本工具钩子 |
| Claude Code      | 用户级 `PreToolUse`                            | 配置合并、移除和守卫载荷测试通过；需重启，未宣称各版本真实会话均已实测              |
| OpenCode         | `tool.execute.before` 插件                     | 插件生成、配置生命周期与载荷测试通过；需重启，未完成各版本宿主会话实测              |
| ZCode            | 用户级 hooks                                   | 配置合并、移除和守卫载荷测试通过；需重启，未宣称宿主会话已验证                      |
| DeepSeek Harness | 内置 Claude hooks 桥接插件，通过 `insert` 挂载 | 本机插件实现已只读核实，配置生命周期和载荷测试通过；需重启，未宣称宿主会话已验证    |
| WisCode          | 有限配置体检                                   | 尚未核实公开的执行前钩子，界面明确标为暂不支持拦截                                  |

“配置已写入”和“规则自检通过”分别证明配置存在、独立守卫能判定，不证明当前运行的工具已加载它。真实钩子事件可提供运行证据，但历史事件不能证明之后的会话仍开启防护。

Codex 的“信任此防护”读取官方 `hooks/list` 返回的当前钩子哈希，通过 `config/batchWrite` 仅保存匹配本工具命令、来源及事件的信任项，写入前备份 `config.toml`，使用配置版本防止覆盖并发修改，写入后重新查询并确认。其他钩子、项目信任、审批及沙箱设置保持不变。不支持相关接口的旧版本会提示更新，失败不会显示已信任。配置、钩子或守卫内容发生变化时，界面会要求再次确认。信任成功属于配置操作记录，不计作真实拦截。

命令检查采用文本规则，支持常见直接命令及文件工具路径。变量拼接、脚本内部、工具未上报的访问等并非完整覆盖；该工具不能替代沙箱或操作系统访问控制。工具钩子超时或崩溃时可能放行，安全中心不会声称已阻断。文件权限 600 限制其他系统账户，不能隔离同一账户运行的进程。

回溯扫描同样基于文本规则，只覆盖会话记录中可识别的模式；命中不等于操作执行成功或已造成损害。会话文件超过限额时只扫描最近的一部分并明确标注。历史线索仅用于复核实际影响，不参与当前评分。开启防护无法撤销过去的操作。扫描结果保存在 `security/retro-scan.json`，重新扫描覆盖旧结果；评分快照保存在 `security/history.jsonl`（追加式，展示本版规则的最近 30 条用于趋势图）。

联网巡检观察配置变化，没有采集请求正文或据此认定发生数据外发。事件日志不保存完整命令正文，敏感字段会脱敏。日志使用跨进程锁和哈希链，并保留最近两个约 8MB 的文件；哈希链能检测部分记录变更，不能抵御具有本机写权限的程序重写全部记录。

## 开发验证

- `npm run build`：类型检查、页面与 Electron 守卫构建。
- `npm test`：项目单元测试。使用满足项目要求的 Node；本次完整测试使用本机 Node 24，默认 Node 20 缺少历史测试使用的 SQLite/Zstandard API。
- `node scripts/verify-security-policy.mjs`：隔离 home 与应用数据目录验证重点清单布局、标签颜色、编辑与持久化；从页面保存，经 IPC 写入 `policy.json`，调用应用复制的守卫验证自定义敏感文件/后缀/主目录通配、分支、路径与命令，并确认关闭读取规则放行、重新开启后下一次调用拦截。载荷只用于判定，不执行命令或读取敏感文件；不代表第三方宿主当前会话已加载钩子。
- `node scripts/verify-security-runtime.mjs`：调用构建后的守卫，检查五种协议载荷及并发日志完整性。
- `node scripts/verify-security-center.mjs`：运行桌面应用，用隔离的应用数据目录走通体检（真实进度）、看板图表与评分快照、回溯扫描、安全报告、项目规则、MCP 检查和巡检页面。用户工具配置只读，规则保存到临时应用目录。
- `npx tsx --test tests/security-stats.test.ts`：看板统计聚合、评分快照、时间线分页/日期筛选、回溯扫描载荷解析、脱敏、限额、去重、元数据误报与历史记录隔离。
- `NETWORK_LENS_TEST_CODEX=/绝对路径/codex node --import tsx --test tests/security-codex-trust.test.ts`：在独立临时 Codex 目录验证官方信任读写、重连后的持久状态及其他钩子未获信任；不复制凭据，不调用模型。

安装与卸载会修改工具的用户配置，只有用户在应用内确认后发生。测试不会替用户给真实工具开启防护。发布安装包仍需要常规签名、安装及平台验收，本次未声称已发布。

**默认开启与用户控制：** 自动开启仅在工具已安装、支持钩子、用户未手动关闭该工具，且全局“默认开启”未关闭时发生；它复用与手动开启相同的“合并本应用条目 + 备份 + 原子写入 + 失败回滚”路径。自动开启不会修改工具的其他设置，不启用 WisCode 这类暂不支持拦截的工具，也不会覆盖用户已有的同名钩子之外的配置。原有配置备份保留在应用数据目录的 `security/backups/`。

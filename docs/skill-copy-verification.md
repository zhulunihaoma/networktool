# Skill 完整复制与自动检查

复制策略保留 `SKILL.md`、元信息、脚本与普通文件的原始内容。不会为通过兼容检查删除字段、删除 `agents/openai.yaml`、追加说明或补写 name。为保证链接在目标目录可用，内部符号链接会实体化；外部链接保留为绝对本机依赖，并在检查结果中说明。无法通过基础检查时报告原因，源目录不会被自动改写。IPC 第四个布尔参数保留以兼容旧调用方，新复制器不据此修改 Skill 内容。新界面遇到旧主进程的 convert 状态时会提示重启，拒绝有损转换。

## 自动流程

1. 预览阶段检查目标路径、源目录安全边界、基础元信息与目标规则。
2. 检查 SKILL.md 中显式的本地 Markdown 资源链接。缺失的目录内资源阻止复制；外部资源标记未验证。不把代码围栏里的示例链接当作依赖，也不把自然语言当作可执行依赖清单。
3. 递归解析符号链接。指向 Skill 内部的文件或目录会展开到链接所在位置，保留文件可执行权限；指向外部的有效文件链接会改写成绝对路径链接并列为本机依赖，外部目录链接保留为依赖且不复制目录内容。失效链接、循环引用、无权限、特殊文件和超限会报告具体路径与原因并阻止该项。
4. 普通文件名包含 `token`、`secret` 等字样不再单独拦截；仅检查文件内容中的高置信度私钥或凭据特征，提示中不回显凭据本身。
5. 同名目标存在时比对归一化后的可访问内容。一致则跳过；不同则预览明确提示“备份后更新”。用户确认后将旧目录原子移动到目标旁的 `.skill-backups`，安装新副本；发生错误时自动恢复旧目录。目标在检查后变化会停止更新。
6. 使用暂存目录复制文件，比较源与暂存副本的 SHA-256。哈希包含相对路径、普通文件内容及可执行权限、目录条目和外部文件依赖内容；内部链接展开后按目标结构核对，外部链接按其解析后的绝对目标核对。资源先发布，SKILL.md 最后发布。
7. 发布后重新读取目标目录，确认哈希一致。不一致时撤销本次发布的条目；备份更新失败时恢复旧目录，并显示未能恢复时的备份位置。
8. 再展示逐项检查结果、规则日期、来源及源/目标哈希，失败项显示具体原因和资源路径。
9. OpenCode 目标批次会自动尝试一次 CLI 发现检查：`opencode --version` 与 `opencode debug skill`。使用绝对可执行文件路径，不使用 shell，不执行 Skill 业务任务。分别限制 3 秒/10 秒，发现输出最多 8 MB。仅接受数组中的 name/location 字段，要求名称及真实绝对路径都与本次目标一致。同名但来自其他目录会报告发现失败。

## 检查结论

- **完整性通过**：源 Skill 的可访问内容与目标副本一致；内部符号链接已实体化，外部依赖仍需留在当前机器。
- **基础格式通过**：符合工具所采用的通用元信息检查。
- **目标规则通过/有差异**：符合内置文档快照或发现扩展字段差异；不意味着当前安装版本必然支持。
- **OpenCode 实际发现通过**：CLI 发现了目标目录的这份 Skill。`debug skill` 不检查每个 Agent 的调用权限，因此不等于可调用或任务执行通过。
- **未验证**：找不到 CLI、命令/输出不支持、超时、其他宿主暂无发现接口，或依赖/权限/业务执行没有验证。不会转换为“成功运行”。

## 验证入口

- `node --import tsx --test tests/skill*.test.ts`：完整性、链接解析、外部依赖、失效/循环链接、内容凭据检测、同名备份更新、资源缺失与发现失败。
- `npm run build`：生成同步的 renderer / preload / main。
- `node scripts/verify-skill-auto-copy.mjs`：真实生产 IPC 流程，使用临时 home 和数据目录，不替换 copy-skills 处理器；验证批量复制和结果显示。

不自动执行任意 Skill 业务任务。通用说明文件未提供可靠的测试输入与成功判据，模型声称“可以使用”也不作为执行证据。MCP 登录、系统权限与依赖安装状态仍单独标为未验证。

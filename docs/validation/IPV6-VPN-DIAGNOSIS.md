# IPv4 / IPv6 与 VPN 路径对照

入口：工具网络诊断 → “连接异常，或经常重连？” → 选择对象 → 按顺序排查 → 安全连接与平台响应。

macOS 下补充检查系统解析地址（每个地址族最多两个）、同一地址的路由接口、TCP/TLS 与无凭证 HEAD 响应。Codex 额外检查 `codex-cloud-backend.chatgpt.com`。补充探测不使用 HTTP/SOCKS 代理，也不模拟应用认证、WebSocket 或模型请求。HTTP 401/403 不能视为应用恢复。

仅当 IPv4 通过隧道完成 TLS、已测 IPv6 经其他接口全部失败、存在公网 IPv6、检查期间网络未变化、唯一对应 Wi-Fi 服务的原设置为 Automatic，并且系统代理选择 DIRECT 时，展示“仅本地链路 IPv6”的手动验证方案。界面列明作用范围、修复命令、恢复命令和原工具复测步骤；程序不执行 sudo，不读取密码，不修改系统。

复制方案前重新检查接口签名、服务身份、配置及十分钟时效。手动/未知配置、双栈都失败、路由缺失或 Windows 等系统不提供该 macOS 修复命令。复制整段方案时，恢复命令被注释，避免立即撤销修复。

处理后重新检查时，接入网络比较使用物理 IPv4 接口摘要，避免把限制 IPv6 本身当作切网；若接入网络不同，明确提示不能归因为修复成功。同一排查窗口保存原设置的恢复方案，应用重启后不保留，用户应复制报告保存。需要在原工具连续测试消息并独立确认恢复。

验证命令：

```sh
node --import tsx --test tests/ip-path.test.ts tests/triage.test.ts
npm run build
node scripts/verify-ip-path-ui.mjs
```

单元及依赖注入测试覆盖判定门槛、失败与缺失证据、服务名转义、配置漂移、过期与切网、原设置恢复、取消和不泄露网络摘要。Electron 界面验收使用隔离数据，不联网、不修改真实系统设置。真实热点下的网络与原应用恢复需要另行现场验证，不能以界面夹具代替。

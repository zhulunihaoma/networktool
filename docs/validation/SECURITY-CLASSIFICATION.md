# 资源分类误判修复验证

日期：2026-11-12。

本次修改资源分级、操作类型和追踪链展示所用的分类逻辑。防护规则的允许/拒绝判断保持原有实现，命令不会因分类测试而被执行。

## 根因与修正

旧版对整段命令匹配关键词，无法区分程序名、搜索词、内联脚本和 heredoc 正文。新版先识别 shell 命令边界、引用、转向、已知包装器和显式 shell 执行，再按客户端和参数用途分类。

| 场景 | 旧问题 | 修正行为 |
| --- | --- | --- |
| Node/Python 检查 SQLite 模块 | `sqlite` 被当成数据库访问 | 仅记录解释器执行，不产生数据库节点 |
| 搜索 `mysql`、`kubectl`、`.env` 或 URL | 搜索内容被当成访问资源 | 搜索表达式与目标路径分开，只分类实际文件目标 |
| 写入脚本或说明用的 heredoc | 正文中的示例命令被当成真实操作 | 正文作为数据；`sh -c`、shell heredoc 等显式执行另行分析 |
| 客户端帮助和版本 | 启动客户端被当成已连接资源 | `mysql --help`、`sqlite3 --version`、`curl --version` 不产生连接节点 |
| `curl`、`wget` 获取文件 | 默认被当成上传 | 区分下载、请求体上传及上传文件参数 |
| 请求正文中的 URL | 被记录成连接主机 | 只提取目标 URL 的主机，并移除凭据、路径和查询串 |
| `through.ts` 等文件名 | `hr` 子串被判成人事数据 | 英文业务名称按路径段边界匹配 |
| `npm update`、普通代码中的 SQL 单词 | 被当成写操作 | 操作类型来自实际程序；SQL 只分析数据库客户端的查询参数或输入 |

真实的 SQL 查询/写入、文件与凭据读取、云资源命令、上传操作，以及已有防护规则命中，保留对应分类。目录读取 `ls` 补记为文件资源（L2）。

## 历史记录和边界

新记录带 `classifierVersion: 2`。旧记录的 `facts` 原样保留，避免破坏哈希链；追踪链注明旧版分类可能存在关键词误判，刷新不会重新计算历史结果。资源分类表示对操作请求的分析，不能证明服务正在运行、连接成功或操作完成。

这是保守的本地静态分析，不会执行用户脚本来推测行为，也不解析任意语言源码、外部脚本文件、动态变量命令或所有 shell 扩展。遇到无法确定的脚本内容，保留已知执行动作，不从其中的词汇编造资源。内联脚本内部真正访问的资源可能因此无法分类；规则命中仍单独保留。

执行前防护与资源分类是两条逻辑。在构建产物验证期间，当前运行的钩子曾因测试载荷字符串中含 `cat .env` 而阻止启动该验证命令，属于仍需单独评估的保守拦截行为。本次使用不含敏感读取字面量的 6 组输入完成构建产物验证；凭据判定由已有源代码回归测试覆盖，没有关闭或绕过运行中的防护。

构建产物位于 `dist/` 和 `dist-electron/`。已运行的应用及其复制的 guard 脚本需通过应用正常重启/初始化更新后，后续记录才使用新版逻辑。

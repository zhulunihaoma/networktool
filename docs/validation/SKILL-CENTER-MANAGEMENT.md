# Skill 中心管理流程与验证

## 管理范围与入口

工具 Tab 与搜索决定安装项范围；“全部安装 / 重复整理 / 安全风险 / 低频建议”决定当前视图。Tab 徽章仍按各工具扫描到的安装项计数，完整目录哈希用于统计已核对的内容版本，不将未知项推断成独立版本。

## 重复整理

- 按真实位置、完整目录指纹、同名关系形成不重叠的分组。同组可以包含相同副本和不同版本。
- 默认仅合并展示。用户可比较文件的内容、权限与链接差异；大文件只展示摘要并标明未展开，比较仍使用完整文件哈希。
- 选择来源版本后，可进入原有复制预检流程，将其他工具的同名版本备份后更新。
- 只允许清理同工具、同目录名、内容一致的普通副本。共享目录、安装源管理目录、已保留项、有链接或子 Skill 引用的项目不参与合并清理。
- 合并预览显示保留路径和移入回收区路径。用户核对工具加载配置并确认后执行，主进程重新校验所有副本和保留项。
- 一组未全部成功时，恢复本组已经移动的副本；恢复失败则明确保留回收区记录供重试。关闭结果（包括 Escape）先刷新列表。
- 本机其他应用仍可能自行修改文件；预检失效时重新扫描。只覆盖已扫描到的链接依赖，不声称掌握所有工具的自定义加载配置。

## 整理建议

"重复整理"视图顶部的整理建议只覆盖有本机证据的场景，跨工具副本默认各自保留。分析只读，结果带 10 分钟一次性令牌；执行前逐项重新核对内容摘要（忽略权限位）和目录 inode，保留版本也一并核对，任何变化都跳过该项。

| 场景 | 识别依据 | 按钮动作 | 撤销 |
| --- | --- | --- | --- |
| WisCode 投射目录中的同名旧副本 | `~/.wiscode/codex-agents/skills/X` 是实体目录、未登记在 `.wiscode-skill-ownership.json`，且 `~/.wiscode/skills/X` 存在；附带 WisCode 日志中的 `codex-skill-target-conflict` 记录 | 移入回收区，WisCode 下次同步重建链接 | 回收区恢复（记录 `protectedRoot`，允许写回投射目录） |
| 与包内子 Skill 完全相同的独立副本 | 同一工具目录内，独立目录与另一包内同名子 Skill 内容摘要一致 | 移入回收区 | 回收区恢复 |
| Codex 旧用户目录 | `~/.codex/skills/X`（不含 `.system`）；官方用户级目录为 `$HOME/.agents/skills` | 迁移到 `~/.agents/skills`；目标已有相同副本则移入回收区；目标有不同版本则不可执行 | 迁移记录 `~/.network-lens/skill-moves.json`，本页撤销 |
| 多个工具中的同名版本不一致 | 顶层同名目录内容摘要不同；以最近修改时间作为候选来源 | 打开现有复制流程（兼容、风险检查与旧目录备份）；超过 500 文件 / 20 MB 不可执行 | 复制流程的备份 |
| 安装器管理的副本 | 目录内 `.<owner>-managed-skills.json` | 仅说明，不提供按钮 | — |

二次确认弹窗列出每一项路径、处理后生效的位置、内容是否一致、提示与版本对照，可逐项取消勾选；必须勾选确认语句才能执行。结果逐项显示完成、跳过或失败及原因。

## AI 盒子安全整合

- 安装清单复用已有 Skill 内容扫描和 MCP 配置检查。MCP 首版识别独立的 `mcp.json` / `.mcp.json` 文件，不执行 Skill 或启动 MCP。
- 详情显示脱敏证据、文件行号、扫描范围、所属工具防护状态，以及明确标注为工具级的近期真实防护记录。没有直接归因证据时，不把工具事件归因于当前 Skill。
- 高、中风险支持“暂不处理本版本”和恢复提醒。决定绑定完整内容指纹与规则版本，内容变化后自动失效；这不会放宽复制前确认或运行时防护规则。
- 文件不可读、二进制、链接依赖或大小/数量限制均体现为检查不完整；未命中规则不表示完整安全。
- 主进程将本次扫描摘要交给安全中心展示。静态扫描记为 `scan` 来源，不计入真实检查/拦截数量，Skill 风险数量不参与配置风险扣分；原有审计链校验加分口径保持不变。

## 使用证据与低频建议

- 首版支持 `.codex/skills`、`.agents/skills` 对应的 Codex 本地会话日志。其他工具显示不支持，继续观察。
- 读取请求必须精确对应 `SKILL.md` 的文件参数；提到名称、echo、路径前缀相同、失败读取均不计入确认加载次数。同会话重复读取计一次。
- 会话加载占比 = 近 30 天确认加载会话 / 同期可读取日志中的有效工具调用会话。分母为零、覆盖不完整或不支持时不显示百分比。
- 首次发现满 30 天、最近 14 天无内容更新、可读取日志跨度至少 30 天、近 30 天至少 20 个有效会话、日志未遇到预算/解析缺口，才评估低频。日志是可见证据范围，不覆盖工具未写入日志的隐式加载。
- 近 30 天确认加载 1 次只标记低频；0 次给出“可考虑清理”；观察跨度和距最后确认加载均达到 60 天时给出“建议清理”。首次发现时间是安装时间未知时的保守起点。
- 共享、链接、嵌套、安装源管理、被已知资源链接引用或用户标记保留的安装项退出批量低频清理。
- 日志最多读取 400 个文件、单文件 8 MB、累计 64 MB；无法解析的封装调用视为覆盖缺口，不输出“从未使用”。目前不解析 `functions.exec` 内的任意 JavaScript。
- 保留、暂不处理和首次发现/内容变化时间存放在用户目录的 `.network-lens/skill-catalog.json`，不修改 Skill 原文。元数据无法保存时停止生成低频清理建议。

## 验证命令

```sh
node --import tsx --test tests/skill-insights.test.ts tests/skill-cleanup.test.ts tests/skill-tidy.test.ts tests/skills.test.ts tests/skill-verification.test.ts tests/skill-auto-repair.test.ts tests/security-skill-scan.test.ts tests/security-center.test.ts tests/security-stats.test.ts
npm run build
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node --import tsx scripts/verify-skill-insights.cjs
```

UI 脚本要求本地开发服务可用（默认 `http://127.0.0.1:5173`，可设置 `SKILL_UI_URL`）。它只在隔离临时目录创建 Skill、日志和观察记录，直接调用真实扫描器；浏览器侧通过测试桥接接口连接，不操作实际用户安装。验证重复比较、合并确认、Escape 刷新、回收区恢复、版本更新预检、安全详情、风险忽略/恢复、低频建议、保留排除及 1440/1024/768 窗口布局。

此验证覆盖真实文件后端与浏览器交互，不等同于实际安装工具的加载验证或真实攻击拦截验证。
